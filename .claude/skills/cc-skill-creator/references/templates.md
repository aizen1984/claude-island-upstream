# Skill 创建模板与质量清单

> cc-skill-creator 的参考资料。创建新 Skill 时按需加载。

---

## 一、SKILL.md 模板

```yaml
---
name: {skill-name}
description: {动词}+{做什么}+{用于...场景}（80-150字符）
---
```

```markdown
# {Skill 标题}

## Overview

{一句话定位} + {核心特点列表}

---

## When to Use

| 场景 | 是否适用 | 说明 |
|------|---------|------|

---

## 协作关系

- **接收自**: {来源 Skill}
- **委托给**: {目标 Skill}
- **隐式依赖**: {规范库}

> 详细协作矩阵见 `shared-rules/skill-orchestration.md`

---

## 资源加载指导

| 场景 | 加载文件 |
|------|---------|

---

## 核心流程

{步骤 1-N}

---

## Gotchas

> 从实际使用中积累的常见陷阱。每次发现新问题时追加。
> **位置规则**：SKILL.md > 200 行时 Gotchas 放 frontmatter 之后（primacy effect）；<= 200 行放末尾。

| # | 陷阱 | 后果 | 正确做法 |
|---|------|------|---------|
| 1 | [问题描述] | [不处理会怎样] | [应该怎么做] |
```

**推荐章节顺序**（按认知负载优化）：

| 顺序 | 章节 | 必选 | 说明 |
|------|------|------|------|
| 1 | Gotchas（>200行时） | 条件 | 前置避坑，primacy effect |
| 2 | Overview | 必选 | 一句话定位 + 核心特点 |
| 3 | When to Use / 不适用场景 | 必选 | 边界定义，避免误触发 |
| 4 | 协作关系 | 推荐 | 接收自/委托给/隐式依赖 |
| 5 | 资源加载指导 | 推荐 | 条件矩阵（含"不加载"列） |
| 6 | 预思考 | 条件 | 需要 cc-think-first 的 Skill |
| 7 | 核心流程/原则 | 必选 | Skill 的主体内容 |
| 8 | 数据契约/输出配置 | 推荐 | 输入输出格式 |
| 9 | 成功标准 | 推荐 | 量化验收条件 |
| 10 | FAQ | 可选 | 常见问题快速答 |
| 11 | Gotchas（≤200行时） | 条件 | 短文件放末尾 |

## 二、目录结构模板

```
{skill-name}/
├── SKILL.md              # 必须。核心入口 ≤ 500 行
├── workflows.md          # 可选。详细流程步骤
├── prompts.md            # 可选。Subagent 提示词模板
├── resources.md          # 可选。调用示例、数据格式
├── references/           # 可选。按需加载的参考文档
│   └── {topic}.md
└── scripts/              # 可选。确定性脚本
    └── {script}.py
```

## 三、质量检查清单

创建/修改 Skill 后，逐项检查：

### D1: 核心流程（必须）
- [ ] 有明确的步骤序列（不是散文描述）
- [ ] 每步有明确的输入/输出
- [ ] 有判断条件（if/else 分支）

### D2: 错误处理（必须）
- [ ] 列出了常见错误场景
- [ ] 每个错误有恢复策略（重试/回退/上报）
- [ ] 有超时保护

### D3: 协作接口（推荐）
- [ ] 声明了接收自/委托给
- [ ] 声明了隐式依赖
- [ ] 列出了禁止行为（不允许做什么）

### D4: 子文件组织（推荐）
- [ ] SKILL.md ≤ 500 行
- [ ] 子文件有按需加载指导（资源加载指导表）
- [ ] 无 > 500 行的子文件（有则加标题索引）

### D5: 产出质量标准（推荐）
- [ ] 有量化指标或检查清单
- [ ] 有输出格式规范
- [ ] 有成功/失败判定标准

## 四、Description 编写指南

**格式**：`{第三人称动词} + {做什么} + 。用于{场景1}、{场景2}`

**好的例子**：
- `对代码执行九维度审查（安全/架构/数据完整性等），支持建议式和阻断式。用于PR审查、代码质量检查`
- `通过Firekylin API代理执行生产数据库只读查询。用于查表结构、查数据、SELECT/SHOW/DESCRIBE`

**差的例子**：
- `代码审查工具` — 太短，缺 "用于" 触发条件
- `一个很好的代码审查 Skill，支持很多功能` — 废话，缺具体能力

**长度**：80-150 字符。当前 L0 预算 ≤ 20000 字符（2% of 1M context）。
