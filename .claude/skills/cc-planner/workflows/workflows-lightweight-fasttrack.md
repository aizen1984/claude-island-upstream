# 轻量快速通道 & RIPER 触发标准

## RIPER 触发标准（2 步快判）

```
Step 0: Bug Fix？（优先于 Step 1/2 判断）
  □ 有明确报错信息/堆栈/复现步骤
  □ 修复范围可预判（1-3 文件）
  → 全满足 → Bug Fix 快速通道：
    RESEARCH(精简:定位根因,≤5min)
    → PLAN(精简:bugfix spec + 修复任务,内嵌plan.md)
    → EXECUTE(委托 code-writer Bug Fix 流程执行修复)
    → REVIEW(精简:验证修复+无回归)
    跳过: INQUIRE + DESIGN + DESIGN-REVIEW
    注: planner 负责定位根因和拆解修复任务，code-writer 负责编码执行

Step 1: 强制触发？（任一即触发完整 RIPER）
  □ 涉及网络搜索/文档阅读
  □ 用户明确要求规划
  □ 外部系统集成
  → 命中任一 → 完整 RIPER

Step 2: 可跳过？（全部满足即输出简化计划）
  □ 单文件 + 步骤明确
  □ 纯机械性任务 或 用户已提供完整步骤
  □ 无需决策/无歧义
  → 全满足 → 简化计划（不走完整 RIPER）

其他 → 检查条件触发（满足 2 项即完整 RIPER）：
  外部调研 | 步骤不可预测 | 多文件(3+) | 跨模块(2+) | 决策点多(2+) | 预估>15min
```

## 轻量快速通道（小型任务）

**触发条件**：同时满足以下全部条件时自动进入：
- 任务数 ≤ 3
- 预估 LOC ≤ 50
- 无跨模块依赖
- 用户未明确要求完整规划

**与标准模式的对比**：

| 模式 | 任务规模 | 五文件持久化 | 阶段 | 设计评审 |
|------|---------|------------|------|---------|
| 轻量快速通道 | ≤3任务/≤50LOC | 可选（≤2任务可内联） | R→P→E→R（简化） | 跳过 G4/G5 |
| 标准模式 | >3任务 | 必须创建全部文件 | 全五阶段 | 完整 |

**轻量快速通道流程**：
1. **Research**：1-3 句话确认问题和影响范围
2. **Plan**：≤2 任务可在对话中内联列出；3 任务须写 plan.md
3. **Execute**：直接执行，无需用户确认（除非有不确定性）
4. **Review**：≤2 任务内联验证即可；3 任务做简要检查

**退出条件**：执行中发现实际复杂度超出预期（任务数>3 或 LOC>50 或出现跨模块依赖），立即升级为标准模式。
