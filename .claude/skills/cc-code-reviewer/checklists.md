## 完整审查清单（70 项）

> 用途: 全面代码审查时使用，按优先级排序

### P0 - 安全审查（6 项）

```
[ ] SQL 查询使用参数化（PreparedStatement / #{} 占位符）
[ ] 日志输出使用参数化 log.info("User: {}", userId)
[ ] 敏感数据（密码/密钥）不得明文存储或日志打印
[ ] 外部输入在使用前必须验证（白名单方式）
[ ] Controller→Service→Repository 参数传递链路：用户输入是否未经校验直接到达 DB 层
[ ] 随机数使用 SecureRandom 而非 Random
```

### P0 - 数据完整性（5 项）

```
[ ] 多表写入添加 @Transactional(rollbackFor = Exception.class)
[ ] 本类调用事务方法必须用 AopContext.currentProxy()
[ ] 并发更新使用悲观锁 findByIdForUpdate()
[ ] 状态转换通过 canTransitionTo() 验证
[ ] 异步执行使用 TransactionSynchronization.afterCommit()
```

### P0 - Java 语言基础（4 项）

```
[ ] 字符串/枚举比较使用 equals() 而非 ==（常量在前：STATUS.equals(var)）。豁免：编译期常量（static final String 字面量）之间的 == 比较在常量池中安全，降级为中置信度建议
[ ] 金额/精度计算禁止使用 double/float，必须使用 BigDecimal（构造用 String 参数：new BigDecimal("0.1")）
[ ] NPE 防护：链式调用前判空，Optional.ofNullable 包装可空值
[ ] 集合判空使用 CollectionUtils.isEmpty() 而非 == null 或 .size() == 0
```

### P0 - 业务行为验证（6 项）

```
[ ] 验收标准是否全部被实现（对照设计文档）
[ ] 正常业务流程是否被覆盖
[ ] 异常业务流程是否有明确处理（用户错误、系统错误）
[ ] 边界条件处理（空值、极值、超时）
[ ] 业务规则是否集中在 Service 层（而非分散）
[ ] 返回给用户的错误信息是否清晰、可操作
```

### P0 - 流程顺序验证（5 项）

```
[ ] 操作顺序符合业务逻辑（先验证 -> 再操作 -> 后通知）
[ ] 状态转换有前置条件校验（canTransitionTo）
[ ] 重复调用结果一致（幂等性）
[ ] 失败有补偿/回滚机制
[ ] 异步操作的顺序依赖是否被正确处理
[ ] 参数传播完整性：调用下层方法/构造 DTO 时，每个传入 null 或未赋值的字段，必须确认下层无使用逻辑（getter 取值、方法调用、条件判断）；有使用则为 bug
```

### P1 - 架构合规（12 项）

```
[ ] Controller 只注入 Service（不直接调用 Repository/Mapper）
[ ] Service 只注入 Repository（不跨层调用 Mapper）
[ ] 异常在 Service 层统一处理（Controller 不捕获业务异常）
[ ] 单一职责：Service 类不超过 500 行，无 5+ 不相关职责
[ ] 开闭原则：新增类型用策略模式，不在 if-else/switch 上追加分支（>= 5 分支）
[ ] 依赖倒置：依赖接口而非具体实现类，禁止 new XxxImpl()
[ ] 无循环依赖（ServiceA ↔ ServiceB）
[ ] DTO 组织正确（Req 在 req/、Resp 在 resp/，不混放 dto/）
[ ] 反重复管道：新策略实现与已有实现共性 > 50% 时，必须提取基类/共享管道，差异点用钩子方法
[ ] 职责归属：类中每个 public 方法的调用者应一致；回调处理 vs 出站调用不应混在同一个类
[ ] 第三供应商测试：假设再来一个同类型实现，复制行数 > 20 行说明抽象不够
[ ] 所有 public 方法必须有完整 JavaDoc（功能描述 + @param + @return + @throws），排除 getter/setter、@Override 简单委托
```

### P2 - 单元测试（6 项）

```
[ ] 使用 Given-When-Then 结构组织测试
[ ] 断言核心业务字段，不只是 assertNotNull
[ ] 异常路径使用 assertThrows 并验证状态码和消息
[ ] 每个测试方法只测一个场景
[ ] 边界条件有专门测试用例（空值、极值、超限）
[ ] Service 方法的正常和异常路径均有覆盖
```

### P3 - 性能优化（9 项）

```
[ ] 批量操作 > 500 条使用 Lists.partition 分批
[ ] 列表查询使用 PageHelper.startPage 分页
[ ] 避免循环内查询数据库（N+1 问题）
[ ] 大文件使用流式处理（不一次性加载内存）
[ ] 异步任务使用线程池执行（不直接 new Thread）
[ ] 避免 TOCTOU：不先检查资源存在再操作，直接操作+捕获异常（如不先 existsById 再 findById）
[ ] 可并行未并行：多个独立 RPC/DB 调用应使用 CompletableFuture 并行而非串行等待
[ ] 无效更新：状态未变化时跳过 update/notify（加变更检测守卫，避免触发无意义的下游通知）
[ ] 热路径膨胀：启动路径/每请求路径不新增阻塞 I/O 或重计算（如配置加载应缓存而非每次读取）
```

### P4 - 设计模式（3 项）

```
[ ] 枚举实现 fromCode()、isTerminal() 方法
[ ] 多策略场景使用策略+工厂模式
[ ] 跨层数据传递使用 Context 上下文对象
```

### P5 - 代码简化（12 项）

```
[ ] 方法不超过 50 行（超过需拆分）
[ ] 条件嵌套不超过 3 层（使用卫语句）
[ ] 无魔法数字（提取为常量）
[ ] 无 @Deprecated 方法（发现即删除）
[ ] 继承方法必须加 @Override
[ ] 无注释掉的代码块
[ ] I/O 资源使用 try-with-resources 管理
[ ] 可能为空的返回值使用 Optional
[ ] 使用 @Nullable/@NonNull 注解标注参数
[ ] MyBatis 查询逻辑（Example/Condition ≥ 3行）已封装到 Repository 语义方法
[ ] 嵌套 ≥ 2 层的 if-else 已应用 Guard Clause 或翻转条件
[ ] 枚举值比较和复合条件已封装为语义辅助方法（isXxx/hasXxx）
[ ] 参数最小化：方法同时接收 A 和 f(A) 时（如 plan + buildUrl(plan.id, plan.code)），f(A) 应下沉到方法内部计算
```

## 审查进度追踪模板

> Phase 与 prompts.md 阶段的映射：Phase 1 = 阶段 0（上下文收集）、Phase 1.5 = 业务上下文、Phase 2 = 阶段 1-9（九维度检查）、Phase 3 = 阶段 10（自我审视）、Phase 3.5 = 阶段 11（对抗验证）、Phase 4 = 输出确认

```markdown
- [ ] **Phase 1: 获取 diff + 识别与上下文（增量聚焦）**
  - [ ] 获取 diff（`git diff` 或变更文件列表），明确新增/修改行
  - [ ] 识别变更类型（Controller/Service/Repository/新功能/Bug修复）
  - [ ] 仅读取改动的直接调用方和被调用方（不扩散到未受影响的旧代码）
  - [ ] 检查相关配置文件（仅改动涉及的）

- [ ] **Phase 1.5: 业务上下文获取**（如提供设计文档）
  - [ ] 读取设计文档，提取验收标准
  - [ ] 理解业务流程和操作顺序

- [ ] **Phase 2: 执行检查清单**
  - [ ] P0 安全（5项） + P0 数据（5项）
  - [ ] P0 业务（6项） + P0 流程（5项）
  - [ ] P1 架构（11项） + P2 测试（6项）
  - [ ] P3 性能（9项） + P4 模式（3项） + P5 简化（10项）

- [ ] **Phase 3: 自我审视**
  - [ ] P0/P1：对每个问题完成完整反向验证（调用链、配置、测试、注释）
  - [ ] P2-P5：对每条建议完成可行性自检（代码锚点 + 可行性 + 收益真实性）
  - [ ] P2-P5 未通过自检的建议已降级为"仅供参考"或已丢弃
  - [ ] 评估置信度（高/中/低）

- [ ] **Phase 3.5: 对抗验证**（阻断式时触发）
  - [ ] 派发独立验证 agent
  - [ ] 综合对比，处理分歧

- [ ] **Phase 4: 输出与确认**
  - [ ] 输出带置信度的问题列表
  - [ ] 询问用户确认 -> 执行修复
```

## 快速审查检查清单

> 用途: 小改动、Bug修复的快速审查

### 审查前准备

- [ ] 阅读 PR/MR 描述，理解变更目的
- [ ] 确认是新功能、Bug 修复还是重构
- [ ] 是否有对应的单元测试

### P0 - 必须修复

**数据完整性**：
- [ ] 多表操作有 @Transactional
- [ ] FOR UPDATE 在事务中
- [ ] 无循环内查数据库（N+1，完整清单归 P3 性能）
- [ ] 无 SQL 注入风险
- [ ] 敏感数据已脱敏

**架构合规**：
- [ ] Controller 不直接注入 Repository/Mapper
- [ ] 无循环依赖

**并发安全**：
- [ ] 共享可变状态有同步保护
- [ ] 无竞态条件（check-then-act 未加锁）
- [ ] 非线程安全类未在多线程环境使用

**资源与异常**：
- [ ] I/O 流在 try-with-resources 中关闭
- [ ] catch 块未吞没异常
- [ ] 事务方法 catch 异常后有重新抛出

### P1 - 建议修复

- [ ] 批量操作分批处理
- [ ] 事务边界合理
- [ ] 有幂等性保障

### P2 - 优化建议

- [ ] if-else <= 5 个分支（超过用策略模式）
- [ ] 无重复代码超过 3 处
- [ ] 方法 <= 50 行

## 按场景速查

| 场景 | 重点检查 |
|------|---------|
| **新增接口** | 权限校验、参数校验、事务边界 |
| **修改查询** | N+1、索引、分页 |
| **涉及金额** | 事务、幂等、精度 |
| **批量操作** | 分批处理、内存、超时 |
| **并发场景** | 锁、事务隔离级别 |
| **外部调用** | 超时、重试、熔断 |
| **定时任务** | 幂等、超时控制、分片、分布式锁 |
| **消息队列** | 消费幂等、消息顺序、死信处理 |
| **文件处理** | 资源释放、大文件流式、路径安全 |
| **第三方集成** | 超时设置、熔断降级、日志脱敏 |

### 场景检查清单

#### 定时任务

- [ ] P0: 执行时间可能超过调度间隔 / 无幂等保护 / 无分布式锁 / 异常被吞没
- [ ] P1: 无超时控制 / 大数据量未分批 / 无执行日志 / 失败无告警

#### 消息队列

- [ ] P0: 消费逻辑非幂等 / 异常导致消息丢失 / 消费者阻塞导致堆积
- [ ] P1: 无重试机制 / 无死信队列 / 消费超时未设置

#### 文件处理

- [ ] P0: 文件流未关闭 / 大文件一次性加载 / 路径穿越风险 / 未校验类型大小
- [ ] P1: 临时文件未清理 / 无上传大小限制 / 文件名未安全处理

#### 第三方集成

- [ ] P0: 无超时设置 / 敏感信息明文传输 / 响应未校验
- [ ] P1: 无熔断降级 / 无重试机制 / 无调用日志

## 快速定位问题

| 关注点 | 快速检查方法 |
|-------|------------|
| 数据库操作 | 搜索 `repository`、`mapper`、`@Transactional` |
| 并发问题 | 搜索 `synchronized`、`Lock`、`Atomic` |
| 异常处理 | 搜索 `catch`、`throw` |
| 资源释放 | 搜索 `close`、`try-with-resources` |
| 外部调用 | 搜索 `FeignClient`、`RestTemplate`、`HttpClient` |
| 空参数传播 | diff 中新增的方法调用/DTO 构造，逐个检查 setter 是否齐全，缺失的追踪下层 getter 使用 |

## 常见误报清单（快速版）

| 疑似问题 | 可能无需修复的情况 |
|---------|------------------|
| 方法超过 50 行 | 逻辑连贯、无法合理拆分的流程代码 |
| 循环内有数据库查询 | 已使用批量查询 + 本地缓存优化 |
| 捕获 Exception | finally 块中用于资源清理 |
| 无事务注解 | 只读查询场景 |
| 硬编码字符串 | 日志消息、测试代码 |
| 嵌套 if 超过 3 层 | 校验逻辑，早返回模式 |
| 代码注释标注"SQL 注入""不安全"等 | 追踪实际代码路径验证，注释可能是历史遗留 |

> 完整误报清单详见 `rules.md` 误报处理章节
