# 询问协议（Inquiry Protocol）

> **加载时机**：需求模糊时按需加载。全局 CLAUDE.md「务必停下来询问」原则的操作化细化。

## §1 三步决策树

### Step 0: 快速通道（全满足 → 跳过询问，一句话确认后执行）

- F1. 用户指令完全明确（无歧义、无缺失信息）
- F2. 所有决策点只有一种合理选择
- F3. 有完全匹配的现有实现模式可参考
- F4. 影响范围单一（代码类: ≤2文件/≤50LOC；工具类: 操作目标明确）

### Step 1: 红线检测（任一命中 → 强制 L3 结构化询问）

| # | 红线条件 | 示例 |
|---|---------|------|
| R1 | 不可逆操作（删除数据、修改生产配置、force push） | DROP TABLE、DELETE FROM |
| R2 | 金额/支付/财务逻辑 | 支付金额计算、退款流程 |
| R3 | 多表联动状态变更 | 订单+库存+支付同时更新 |
| R4 | 含"或"且未选择 | "同步或异步处理" |
| R5 | 新增/修改公共接口签名 | 改 Feign 接口、改公共 DTO |
| R6 | 跨系统/跨服务集成 | 对接外部 API、跨微服务调用 |
| R7 | 架构级变更 | 新增 MQ 消费者、改表结构 |
| R8 | 用户权限/安全策略变更 | 修改鉴权逻辑、改角色权限 |

### Step 2: 条件检查（布尔判断，非红线/非快速通道时）

| # | 检查条件 | 验证方式 |
|---|---------|---------|
| C1 | 能复述完整需求（无遗漏） | 尝试复述，检查是否有"我假设..."部分 |
| C2 | 实现路径明确（只有 1 种合理方案） | 列出候选方案，检查是否唯一 |
| C3 | 影响范围可控 | Grep/Glob 验证引用关系 |
| C4 | 边界条件已知 | 检查是否有 TODO/TBD 标记 |
| C5 | 有可参考的现有实现 | Read 确认存在类似代码 |

**决策**：C1-C5 全通过 → 自主执行 | C1 通过 + ≥2 通过 → L2 简要询问 | C1 未通过或 ≥3 未通过 → L3 结构化询问

## §2 自主研究协议（询问前置要求）

### 研究升级阶梯

遇到不确定性时（技术方案、架构选型、实现思路），**按顺序逐级研究**，每级研究后重新评估确信度，确信即停：

| 级别 | 研究源 | 适用场景 | 工具 |
|------|--------|---------|------|
| S1 代码库 | 当前代码 + Git 历史 | 实现模式、现有约定、调用关系 | Grep/Glob/Read/git log |
| S2 知识库 | Obsidian Vault | 表结构、字段含义、业务域概念、历史设计决策 | obsidian search |
| S3 网络 | 互联网最佳实践 | 技术选型、架构模式、方法论、性能优化、安全实践 | WebSearch/WebFetch |

**升级规则**：S1 未解决 → S2 → S2 未解决 → S3 → S3 仍不确定 → 向用户询问（L3），附带已研究结果

### S3 网络研究触发条件（任一命中）

- 多种可行技术方案，无法仅从代码库/知识库判断优劣
- 架构设计决策（消息队列选型、缓存策略、分库分表、并发模型、事务策略）
- 性能优化方向不明确（索引策略、批处理方案、连接池配置）
- 安全实践 / 合规要求不确定
- 新框架 / 新工具 / 新版本的推荐使用模式
- 最佳实践可能已演进（如 Java 21 虚拟线程 vs 传统线程池）

### S3 网络研究要求

1. 搜索关键词包含定向词："best practice" / "recommended" / "production" / "vs" / "comparison"
2. 信源优先级：官方文档 > 权威技术博客 > Stack Overflow 高票回答 > 社区讨论
   - **Agent / Skill / MCP / Claude Code 相关主题**：必须优先搜索 Anthropic 官方文档（docs.anthropic.com），以官方为准，社区资料仅作补充
3. 综合 ≥2 个独立信息源后形成判断，不依赖单一来源
4. 研究后标注决策依据：`[基于: {来源摘要}]`

### 自主模式特别规则

当 C1-C5 全通过（自主执行）或用户明确授权自主决策时：

- **禁止跳过研究直接猜测** — 不确定时走研究阶梯，不凭经验猜
- **研究结果可直接决策** — 无需额外询问用户确认
- 在输出中简要说明研究发现和选择理由

### L3 询问要求

向用户提问前，必须先完成研究阶梯（至少 S1+S2，符合触发条件时含 S3）。若自主研究解决 → 降级为 L1。

**携带具体信息提问**：询问时必须附带文件路径+行号、代码片段、候选方案 + 已研究的结果摘要。禁止空泛提问（如"这个怎么处理？"）。

## §3 询问格式

- **L1 内联**：正文中附 `[假设: X]`，用户不回复即默认同意
- **L2 简要**：`**需确认**: [问题]，建议[默认选项]`
- **L3 结构化**：Tell（一句话复述理解）→ Ask（具体问题 + 选项 + 默认推荐）

**反过度询问**：同一决策点最多 2 次；第 2 次未明确回答 → 采用默认值并标注 `[假设]`

## §4 认知卫生（核心禁止行为）

| # | 禁止行为 |
|---|---------|
| X1 | 假装理解然后猜测（必须明确承认不确定性） |
| X4 | 连续做出 2 个未经 Read/Grep 验证的假设 |
| X5 | 红线场景下自主决策（必须 L3） |
| X6 | 一次询问超过 6 个问题（分批，每批最多 4-6 个） |
