# Subagent 预算约束

> **加载时机**：派发 subagent 时。防止 subagent 因上下文溢出而失败的强制规则。
> **原文件**：从 `skill-governance.md` §Subagent 预算约束 迁移而来。

## max_turns 强制配置

所有 Task 调用必须设置 `max_turns`：

| 任务类型 | max_turns | 适用场景 |
|---------|-----------|---------|
| 文件创建（纯写入） | 3 | 创建新文件，不需要读取现有代码 |
| 代码修改（读+改） | 6 | 修改现有文件，需要先读取再编辑 |
| 分析任务（读+输出） | 5 | 读取代码并输出分析报告 |
| 复杂实现（多步操作） | 10 | 涉及多文件创建/修改 |

## Subagent 行为约束

> Prompt 大小约束由 `subagent-budget-guard.js` Hook 自动检查（prompt < ~2500 字 / 8000 字符、代码 < 150 行），此处不重复。

按任务类型在 prompt 中添加范围限制：创建型→"不要探索代码库"；修改型→"只读目标文件+直接依赖"；分析型→"只读指定范围"。

## 通用 Anti-Pattern 清单

> 所有 subagent prompt 必须包含以下通用约束。角色特定约束见各 Skill 的 prompts.md。

````
### 通用强制约束
1. **范围限制**: 不要广泛探索代码库。只读取/处理 prompt 中指定的目标文件。
2. **幻觉防护**: 引用的类名、方法名、路径必须来自 prompt 或 Read 工具确认。禁止编造不存在的类或方法。
3. **失败处理**: 同一操作失败 2 次后换方法或标记失败并停止，禁止无限重试。
4. **输出限制**: 单次文本回复不超过 200 行。超出时优先保留结论，压缩过程。
5. **Write 工具守卫**: 禁止用 Write 工具一次性写入超过 200 行的文件。超过时必须：
   - 优先用 Edit 工具（只传 diff，token 消耗极低）
   - 若是新建大文件：先 Write 骨架（< 100 行），再用 Edit 逐段填充
   - 若无法拆分：标记任务失败，由 Lead 主会话直接完成
````

## 任务粒度的上下文约束

| 约束项 | 限制 | 说明 |
|--------|------|------|
| 单任务生成内容 | < 200 行 | 超过则拆分为多个任务 |
| 单任务读取文件数 | < 5 个 | 超过则精简 prompt 中的参考 |
| 单任务输出文件数 | 1-2 个 | 一个 agent 只创建/修改 1-2 个文件 |
| 单次 Write 文件行数 | < 200 行 | 超过则改用 骨架+Edit 模式或回退给 Lead |

## 并行执行共用算法

> 各 Skill（cc-work-mode、cc-code-writer、cc-planner）已在各自 workflows.md 中内联并行执行算法，核心参数：MAX_CONCURRENT=10, MAX_RETRY=3，含冲突检测和重试策略。

## 状态继承矩阵

> 明确 Lead 与 SubAgent 之间的信息边界，防止 prompt 膨胀和交叉污染。

### Lead -> SubAgent 传递规则

| 状态类型 | 继承策略 | 说明 |
|---------|---------|------|
| 任务描述（prompt） | 继承 | SubAgent 的唯一输入，必须自包含 |
| 项目路径/分支 | 继承 | 通过 prompt 注入，非隐式传递 |
| 代码片段上下文 | 继承 | 通过 prompt 注入（< 150 行限制） |
| 对话历史（messages） | 隔离 | SubAgent 从空白对话开始 |
| 其他 SubAgent 结果 | 隔离 | 避免交叉污染，Lead 负责合并 |
| Lead 的推理过程 | 隔离 | 只传结论，不传过程 |
| 全局规则（shared-rules） | 按需 | 仅注入与任务相关的规则片段 |
| 先前同类任务模式 | 按需 | Lead 已完成类似任务时，传入 PRIOR_APPROACH_SUMMARY |

### SubAgent -> Lead 回传规则

| 产出类型 | 回传方式 | 说明 |
|---------|---------|------|
| 最终结果文本 | Task 返回值 | SubAgent 的 result 字段 |
| 创建/修改的文件 | 文件系统 | Lead 通过 Read 验证 |
| 中间推理过程 | 不回传 | SubAgent 内部消化 |
| 错误信息 | Task 返回值 | 失败时的 error 字段 |
