# CC Review - 代码简化 + 九维度审查

两阶段代码审查：先自动修复代码质量问题，再执行深度审查。

## 参数解析

参数: $ARGUMENTS

支持以下格式：
- `/cc-review` — 审查当前 git diff 的所有变更
- `/cc-review path/to/file` — 审查指定文件
- `/cc-review --skip-simplify` — 跳过简化阶段，只执行九维度审查
- `/cc-review --only-simplify` — 只执行简化，不执行审查

## 流程

### 阶段 0: 确定审查范围

1. 如果参数指定了文件路径，审查该文件
2. 否则，运行 `git diff --name-only` 和 `git diff --cached --name-only` 获取变更文件列表
3. 如果没有任何变更，告知用户并退出

### 阶段 1: Simplify（代码简化）

> 跳过条件：参数包含 `--skip-simplify`

调用 `/simplify` skill 对变更代码执行自动简化：
- 减少不必要的复杂度和嵌套
- 消除冗余代码和抽象
- 应用项目编码规范
- **保持功能不变**

完成后向用户报告简化了哪些内容。

### 阶段 2: 九维度审查

> 跳过条件：参数包含 `--only-simplify`

调用 `/cc-code-reviewer` skill 对代码执行深度审查：
- 九个维度：安全、数据完整性、业务行为、流程顺序、架构、单元测试、性能、设计模式、代码简化
- 增量优先：只审查 diff，不主动审查未变更的旧代码
- 输出带置信度的问题列表

### 阶段 3: 汇总

输出两阶段的综合结果：

```
## CC Review 汇总

### Simplify 阶段
- {简化了什么 / 已跳过}

### 九维度审查
- P0: {数量} 个问题
- P1: {数量} 个问题
- P2-P5: {数量} 个建议
- {详细问题列表}

### 下一步
- {建议的修复行动}
```

## 约束

- Simplify 阶段可以修改代码（它的职责就是自动修复）
- 九维度审查阶段**只读**，不修改代码
- 两阶段之间，如果 Simplify 修改了代码，审查阶段基于修改后的代码执行
