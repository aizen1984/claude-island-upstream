# CC Report QC — 统计分析报告质检

对指定的分析报告文件执行质量检查，基于 Assertion-Evidence + SCQA + 认知科学叙事规则。

## 输入

`$ARGUMENTS` = 报告文件路径（如 `/Users/caochen/tools/shuhe-kb/数禾项目/vipship/运维/T0扣款成功率下降全景分析-202603.md`）

无参数时，检查当前对话中最近一次生成的报告内容。

## 执行步骤

### 1. 读取报告

Read 目标文件全文。如果文件超过 300 行，分段读取。

### 2. 逐维度检查

按以下 5 个维度打分（每维度 1-10 分），每个维度列出具体问题：

#### D1 结构完整性（SCQA + 四幕）

| 检查项 | 通过标准 |
|--------|---------|
| S 情境 | 有 1-2 句共识事实锚定读者 |
| C 冲突 | 有明确的"反常/问题"陈述 |
| A 答案 | 核心结论在前 300 字内出现 |
| 四幕递进 | Hook→递进发现→洞察高潮→行动建议 结构可辨识 |

#### D2 叙事质量（N1-N8）

| 检查项 | 通过标准 |
|--------|---------|
| N1 每层 ≤4 项 | 顶层论点 ≤4 个，每段要点 ≤4 个 |
| N2 结论先行 | 每段首句是结论/断言，非描述 |
| N3 同层 MECE | 同组论点按统一维度（时序/因果/结构），不混用 |
| N4 因果不跳步 | A→B→C 因果链每环有显式连接词 |
| N5 渐进披露 | L0 摘要 → L1 关键证据 → L2 详细过程 层次可辨识 |
| N6 统一术语 | 同一概念全文同一名称 |
| N7 首尾衔接 | 段间有承上启下的桥梁句 |
| **N8 新概念铺垫** | **每张表格/图表上方有「为什么要看这个」的铺垫句；首次引入新指标前有桥梁过渡（上段结论→但还不够→需要从新维度验证→所以看新指标）** |
| **自检**：逆序读每段首句能串成完整逻辑链；每张表格上方有铺垫句 | |

#### D3 数据展示（表格+图表协同）

| 检查项 | 通过标准 |
|--------|---------|
| 断言标题 | 小标题含数字和方向（非描述性） |
| 摘要表格 | 3-5 行关键拐点，有红绿/emoji 变化标注 |
| 图表 | 全区间趋势可视化，图内自解释 |
| 表格图表分工 | 表格=精确拐点值，图表=全貌趋势，不重复 |
| 数字有出处 | 每个数字可追溯到表格行或 SQL 结果 |

#### D4 可验证性 + 诚实原则（最高优先级）

| 检查项 | 通过标准 |
|--------|---------|
| **⛔ 无证据断言** | **逐句扫描：每句断言是否有数据支撑？"用户质量高""效果显著"等修饰语是否跟了具体数字？无数据的断言标为 P0** |
| **⛔ 推测标注** | **不确定的结论是否用 `⚠️ 假设`/`待验证`/`推测` 显式标注？把推测写成结论 = P0** |
| 衍生数字 | 计算过程是否展示（如 `262/273 = 95.9%`），不只给结果 |
| 数字出处 | 每个数字可追溯到表格行或 SQL 结果 |
| SQL 完整 | 每个数据论点有对应 SQL（折叠块内），复制可执行 |
| SQL 带注释 | 字段含义、过滤条件有行内注释 |
| 非 SQL 标注 | 非数据库来源标明数据源+查询方式+时间范围 |
| 查了什么/想证明 | 每个论点有 `> 查了什么` + `> 想证明` 两行 |

#### D5 视觉质量

| 检查项 | 通过标准 |
|--------|---------|
| 图内自解释 | 标题含指标名+对比维度，不依赖图外文字 |
| 信噪比 | 无装饰元素、无一图多义 |
| 渲染引擎 | Obsidian 数据图表用 `chart`，结构图表用 `mermaid` |
| Mermaid 防错 | 通过 9 条防错规则 |
| 表格色彩 | 基线行蓝色、下降红色、上升绿色、不变黑色；变化的数值本身标色 |

#### D6 Markdown 渲染合规（Obsidian 陷阱检查）

| 检查项 | 通过标准 |
|--------|---------|
| 引用块空行 | `>` 多行之间用 `>` + 空行分隔（`>\n>\n>`），不合并成一段 |
| 表格前空行 | 表格上方有空行，不紧跟文字行 |
| SQL 折叠 | Obsidian 用 `> [!note]-` Callout 折叠，不用 `<details>` |
| 内联 HTML | `<span style="color:...">` 用于表格标色，非 Obsidian 时用 emoji 替代 |
| 代码块隔离 | 每个 `chart`/`mermaid` 代码块前后有空行，不与文字粘连 |
| 数字出处 | 每个数字可追溯到表格行或 SQL 结果，衍生计算有公式 |

### 3. 输出质检报告

```markdown
## 📋 报告质检结果

**文件**：{文件路径}
**总分**：{D1-D6 平均}/10
**判定**：✅ 合格（≥8）/ ⚠️ 需改进（6-7）/ ❌ 不合格（<6）

### 各维度评分

| 维度 | 分数 | 关键问题 |
|------|------|---------|
| D1 结构完整性 | X/10 | {问题或"无"} |
| D2 叙事质量 | X/10 | {问题或"无"} |
| D3 数据展示 | X/10 | {问题或"无"} |
| D4 可验证性 | X/10 | {问题或"无"} |
| D5 视觉质量 | X/10 | {问题或"无"} |
| D6 渲染合规 | X/10 | {问题或"无"} |

### 必须修改（P0）
- [ ] {具体问题 + 位置 + 修改建议}

### 建议改进（P1）
- [ ] {具体问题 + 位置 + 修改建议}

### 亮点
- {做得好的地方}
```

### 4. 可选：自动修复

如果用户在参数中加 `--fix`，对 P0 问题直接修改文件。否则只输出报告不改文件。
